1Resumen ejecutivo

El Sistema Web Gestor de Archivos de Audio centraliza los recursos sonoros utilizados por Arca de Salvación Radio 95.3 FM. Permite almacenar, clasificar, buscar, reproducir y administrar audios desde un navegador, sustituyendo el uso de carpetas locales dispersas.

La plataforma conserva en MySQL la información descriptiva y técnica de cada recurso, mientras los archivos binarios permanecen en un almacenamiento protegido del servidor. El acceso está controlado mediante usuarios, roles y permisos. Cada reproducción genera un evento real que alimenta el dashboard y las métricas.

Resultado principal: la emisora dispone de una biblioteca centralizada, trazable, segura y consultable desde computadoras, tabletas y teléfonos autorizados.

2Objetivos

Objetivo general

Proporcionar una aplicación web alojable en hosting PHP/MySQL que permita gestionar de forma organizada y segura los recursos de audio de la emisora.

Objetivos específicos

  • Centralizar archivos y metadatos en una sola plataforma.
  • Reducir el tiempo de localización mediante búsqueda y filtros.
  • Clasificar recursos por categorías adaptadas a la operación radial.
  • Evitar contenido duplicado mediante SHA-256.
  • Controlar el acceso por roles y permisos configurables.
  • Reproducir audio directamente en el navegador.
  • Producir métricas verificables basadas en eventos reales.
  • Permitir a cada usuario administrar su perfil y contraseña.

7Flujos principales de operación

Carga de audio

  1. El usuario autorizado abre el formulario y selecciona MP3 o WAV.
  2. Completa categoría, título y metadatos opcionales.
  3. El servidor valida sesión, permiso, error de carga, tamaño, extensión y contenido.
  4. Calcula SHA-256 y busca coincidencias.
  5. Si existe, cancela e identifica el registro duplicado.
  6. Si es válido, genera nombre aleatorio y mueve el archivo al almacenamiento.
  7. Crea audio y metadatos dentro de una transacción.
  8. Confirma y redirige a la biblioteca.

Reproducción

  1. El usuario abre el detalle y pulsa reproducir.
  2. El servidor vuelve a comprobar sesión, permiso, estado y existencia física.
  3. Entrega el contenido con soporte de rangos.
  4. JavaScript registra un evento al primer play.
  5. Las métricas incorporan el evento real.

Cambio de fotografía

  1. El usuario pulsa la foto o el icono de lápiz.
  2. El navegador valida formato y tamaño y muestra una vista previa.
  3. Al guardar, el servidor repite la validación mediante MIME e inspección de imagen.
  4. Se genera un nombre aleatorio y se actualiza el perfil.

Cambio de contraseña

  1. Introduce contraseña actual, nueva y confirmación.
  2. El servidor verifica la contraseña actual.
  3. Valida mínimo de 8 caracteres y coincidencia.
  4. Genera un nuevo hash y regenera el identificador de sesión.

10Seguridad

  • Contraseñas protegidas mediante password_hash y verificadas con password_verify.
  • Consultas PDO preparadas y emulación desactivada.
  • Regeneración del ID de sesión al autenticar y cambiar contraseña.
  • Cookies HttpOnly y SameSite Lax; opción Secure para producción.
  • Token CSRF en formularios y acciones sensibles.
  • Escape HTML centralizado para prevenir XSS.
  • Autorización repetida en servidor, además de ocultar acciones en la interfaz.
  • Limitación de intentos por identificador e IP hashed durante un período configurable.
  • Mensajes de login genéricos para no revelar la existencia de cuentas.
  • Validación de MIME, extensión, tamaño e imagen real.
  • Rutas físicas y errores SQL no se muestran en producción.
  • Carpetas de almacenamiento protegidas contra acceso directo.
Producción: es obligatorio activar HTTPS, configurar APP_SECURE_COOKIE=true, habilitar fileinfo y mantener .env fuera del repositorio público.

PHP 8.1+, PDO MySQL, mbstring, fileinfo recomendado, MySQL/MariaDB compatible, Apache con mod_rewrite, HTTPS y permisos de escritura en almacenamiento.

Procedimiento resumido

  1. Copiar .env.example como .env.
  2. Crear base utf8mb4.
  3. Importar database/schema.sql y database/seed.sql.
  4. Crear el administrador mediante scripts/create_admin.php.
  5. Conceder escritura a las carpetas de almacenamiento.
  6. Configurar el document root hacia public.
  7. Activar HTTPS, Secure Cookie y copias de seguridad.

15Mantenimiento, respaldo y restauración

El respaldo debe tratar base de datos y almacenamiento como una sola unidad lógica. Un respaldo SQL sin los audios, o viceversa, es incompleto.

Política recomendada

  • Respaldo diario de MySQL con transacción consistente.
  • Compresión de storage/audio y storage/profiles.
  • Copia cifrada fuera del hosting.
  • Retención: 7 diarias, 4 semanales y 6 mensuales.
  • Prueba mensual de restauración.
  • Revisión periódica de espacio, logs, cuentas inactivas y permisos.

Restauración

  1. Poner la aplicación en mantenimiento.
  2. Crear una base vacía e importar el SQL.
  3. Restaurar audios y fotografías preservando nombres.
  4. Configurar rutas y permisos.
  5. Ejecutar pruebas de login, búsqueda, reproducción y carga.
  6. Reabrir después de revisar logs.

16Decisiones técnicas y consideraciones

  • Se eligió MVC ligero sin framework para compatibilidad con hosting compartido.
  • Se añadió RBAC persistido para ampliar permisos sin cambios extensos de código.
  • Se añadió control de intentos de login como requisito de seguridad.
  • Los binarios no se almacenan como BLOB.
  • La duración es editable porque el hosting no garantiza FFmpeg.
  • finfo es el mecanismo principal; existe respaldo por firmas para MAMP local.
  • Bootstrap e iconos se sirven mediante CDN; una instalación aislada debe alojarlos localmente.
  • La eliminación habitual es lógica para preservar métricas y trazabilidad.
No se incorporaron módulos ajenos al alcance, como streaming en vivo, edición de audio, facturación o aplicación móvil nativa.

17Conclusiones

El sistema cumple el objetivo de centralizar y controlar los recursos sonoros de la emisora. Integra persistencia real, seguridad del lado del servidor, administración configurable, reproducción protegida y métricas derivadas de eventos verificables.

Su arquitectura sencilla favorece el mantenimiento y el despliegue en hosting PHP/MySQL. Para producción solo resta completar la configuración propia del proveedor: dominio, HTTPS, límites PHP, usuario MySQL mínimo, rutas externas de almacenamiento y automatización de respaldos.
